# BKMS Workbench

DSH 邮件任务工作台：后台按规则接收新邮件，调用已选技能和工具生成处理结果，将回复草稿交给人工审核。支持多条规则、补充信息、重新生成、发送预览和持久化恢复。

独立私有源码仓库：[zq-ai-labs/bkms-workbench](https://github.com/zq-ai-labs/bkms-workbench)。从 GitHub 恢复时需要配套扩展邮件插件，精确上游版本与补丁步骤见 [恢复说明](docs/RESTORE.md)。

## 启动

本工作区中双击 `启动工作台.cmd`，或运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-workbench.ps1
```

脚本使用映射的 `sources/deepseek-harness` 核心，将本地 `dsh-email` 和 `bkms-workbench` 安装到独立 Profile。默认 HOME 为工作区 `runtime/dev/bkms-workbench/dsh-home`，端口 `9186`。不复制其他实例的模型密钥、邮箱账号或 Session。

首次进入 DSH 后，在设置中配置模型及邮件账号，打开侧栏的「任务工作台」：

1. 在「AI 处理方案」新建方案，用一句话描述需求，点击「AI 生成方案」，核对后保存；也可手动填写。
2. 开启后台处理。首次连接每个邮箱文件夹只建立收件基线，后续新邮件进入任务。
3. 「待我处理」查看摘要、补充缺失信息，或编辑生成的回复草稿。
4. 保存草稿，点击「预览并发送」，核对实际发件账号、To/Cc、正文、附件及收件人策略，再确认发送。

原邮件可独立加载并下载附件；回复草稿可添加或移除附件。上传前需要先保存正文修改，上传后重新预览，避免发送旧版本内容。

关闭页面不影响后台；停止 DSH 服务会暂停处理，下次启动按游标补查。工作台加载期间自动抑制邮件插件的新邮件弹窗，卸载后恢复原通知偏好，不改写邮箱配置。

## 工作台设置

DSH 设置中的「工作台设置」只显示偏好配置，任务列表、AI 处理方案和草稿审核位于侧栏「任务工作台」。

- **显示工作台入口**：默认开启，可即时显示或隐藏侧栏入口。隐藏不暂停后台处理，设置入口始终保留。
- **新待办消息提醒**：默认关闭。开启后，在待审核、待补充、处理失败或发送待核实任务出现时显示简洁文字提醒；可点击查看待办或关闭，8 秒后自动收起。首次连接、重新开启和刷新页面只建立当前待办基线，不补弹历史任务；同一状态的草稿编辑和重复检测不会反复提醒。关闭后立即隐藏当前提醒。
- **邮件检查间隔**：30–3600 秒，默认沿用已有配置，仅在后台处理开启时生效。

偏好保存在当前实例的工作台数据中，与后台处理开关独立；隐藏入口或关闭提醒不会改动邮箱、处理方案、草稿和任务。工作台提醒只在 DSH 界面运行时显示，不申请系统通知权限；关闭页面后后台仍照常处理。

## 全局语言

工作台界面跟随 DSH 全局语言设置，支持中文与英文。侧栏和设置入口、任务状态、AI 处理方案、AI 创建、文件夹选择、运行记录及发送审核实时切换，日期也使用当前语言格式。切换不重建编辑器，未保存的描述、方案和草稿保持原样。

邮件主题、正文、用户方案名称、处理要求、附件名和邮箱自定义文件夹名属于业务内容，不会随界面切换自动翻译。新生成方案的名称与 AI 核对说明采用当前界面语言，处理要求和邮件语言遵循用户明确需求；原有方案不自动改写。已知系统提示在显示时翻译，第三方服务的未知原始错误和 SMTP 回执保留原文。

## 邮件写作与排版

新生成的回复默认使用简明主题、自然称呼、短段落、紧凑事项编号与适当结束语。规则的「处理要求」可自定义语言、语气及署名，例如“使用中文商务语气，署名为：张三 / 客户服务部”。未提供署名时不自动添加工作台品牌、姓名、联系方式或日期。

草稿以纯文本编辑和保存；「预览并发送」展示标准 HTML 邮件样式，实际发送同时携带 HTML 与纯文本版本。中文无衬线字体、14px 字号、1.65 倍行高和 12px 段间距，连续空白行仅在排版中收敛。工作台及邮件插件的草稿预览共用同一渲染器，正文中的 HTML 作为普通文字展示。

重新构建后完全退出 DSH 客户端（包括托盘）再打开。已保存的草稿可以直接使用新排版预览；新的写作规范在后续生成或重新生成时生效，历史内容与人工编辑不会自动改写。此前已发送邮件不会改变。

## 自定义实例

```powershell
powershell -File scripts/start-workbench.ps1 -DshHome D:/my-runtime/workbench -Profile my-workbench -Port 9187
powershell -File scripts/start-workbench.ps1 -Build -PrepareOnly
```

升级本地源码并构建后应重启 DSH 进程；依赖模块的热更新不等价于完整重启。

现有自定义 Profile 也可通过其对应 DSH 命令安装两个本地插件目录，再重启。`dsh-email` 必须使用本次扩展版本；公开 npm `0.16.2` 没有 `emailWorkbench` 服务。不要把工作台直接装进其他用途的生产 HOME 做首次试验。

## 规则

界面名称为「AI 处理方案」（英文 `AI workflows`），目前接入邮件；IM 等其他来源属于后续扩展。内部 `rules` 数据及已有配置保持兼容。新建默认选第一个已配置邮箱及其收件箱，优先级 100、全部条件满足、失败重试 1 次、生成处理摘要与回复草稿、保存后启用方案；全局后台开关单独控制。

邮箱文件夹从服务器读取为下拉选项，支持中文及层级路径，排除不可选容器；选择「全部邮箱」时只列共同路径。读取失败时保留当前选择并提供重试，不要求手工输入。默认收件箱使用邮箱配置中的 `inboxFolder`。

AI 使用 DSH 默认模型生成尚未保存的方案草稿，自动拆分名称、匹配条件、处理要求及必要的可用技能/查询工具。生成阶段不能读取邮件、执行业务或发送。界面展示实际匹配范围和待确认说明，再由用户保存；高级设置可调整筛选、优先级、重试与能力，也保留已有邮件的匹配测试。没有模型或生成失败时可手动填写。

例如：“收到主题包含询价的邮件，整理客户需求并生成中文回复草稿，价格和交期缺少依据时列出待确认事项。”

目前筛选支持发件人包含、主题包含和有附件条件；正文语义、日期、金额或多个独立关键词等筛选不能直接表达。AI 会在待确认说明中提示受限要求，界面的匹配范围是执行依据，不把自然语言说明误当成额外筛选器。

- 多规则按优先级从高到低执行第一条匹配；同优先级按规则 ID 稳定排序。
- 发件人和主题使用不区分大小写的包含匹配，可配置全部条件或任一条件成立。空条件匹配该范围的全部新邮件。
- 规则保存为任务的版本快照；修改或删除规则不影响已排队任务。
- 「测试匹配」仅测试条件，不调用模型。未匹配邮件在「全部任务」中可手动选规则处理。
- 所选技能仅加载其处理说明，不自动扩大工具权限。附件分析需要选择已安装的可信读取工具，例如 `read_document`，文本附件可使用 `str_replace_editor` 的 `view`。
- 默认不开放后台写入和发送。工具目录按已知危险名称过滤；第三方工具没有统一只读声明，仍须确认所选工具实现可信。
- 自动重试最多 3 次；单次 DSH 准备任务最长 5 分钟，串行执行以限制成本和并发冲突。

## 审核与恢复

草稿由邮件插件唯一保存，工作台关联其 ID。人工修改有版本检查；重新生成保留原草稿并创建新的草稿，避免覆盖人工内容。草稿最多 500 份、总存储最多 16 MiB，附件及发送限制沿用邮件插件。

只有明确确认当前预览才发送。收件人禁止规则、账号变化、草稿变化和预览过期会阻止发送。SMTP 接受表示获得提交回执，不保证对方最终投递成功。结果不明不会自动重发，需先核对邮箱。

UIDVALIDITY 变化会停止相应文件夹的增量处理。在规则页的「重建收件基线」确认后恢复；重建时现有邮件不会补处理。

任务存储在 `$DSH_HOME/data/bkms-workbench/workbench-v1.json`，附件位于该目录 `tasks/<任务ID>/`，邮箱草稿在 `$DSH_HOME/data/dsh-email/`。两者需要一起备份。每个 HOME 只允许一个后台 worker；数据写入使用文件锁和原子替换。损坏文件保留并报错，不自动覆盖。

原附件的下载副本暂不自动清理，重复下载会增加本地磁盘占用。任务数据达到 5000 项或 64 MiB 时停止追加并报错，需要先备份归档。

## 当前边界

当前以每封邮件建立任务；同一业务的多封补充邮件自动归并、多人分派、业务系统写入、可视化流程画布尚未实现。报告输出为任务内文本摘要；外部文件生成不是本版默认后台能力。没有配置账号及模型前，工作台仅提供配置和查看入口。

## 开发与验证

```powershell
pnpm install --frozen-lockfile
pnpm run build
pnpm test
$env:DSH_SOURCE_ROOT = 'D:/git/AI/dsh-zq/sources/deepseek-harness'
pnpm test
pnpm run pack:plugin
```

指定 `DSH_SOURCE_ROOT` 时额外执行真实 Cordis/DSH Agent 与 Connection 集成测试，模型和邮箱使用测试替身，不连接真实邮箱或发送真实邮件。详见 `docs/VALIDATION.md`。
