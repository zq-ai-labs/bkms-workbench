# BKMS Workbench

DSH 邮件任务工作台：后台按规则接收新邮件，调用已选技能和工具生成处理结果，将回复草稿交给人工审核。支持多条规则、补充信息、重新生成、发送预览和持久化恢复。

独立私有源码仓库：[zq-ai-labs/bkms-workbench](https://github.com/zq-ai-labs/bkms-workbench)。从 GitHub 恢复时需要配套扩展邮件插件，精确上游版本与补丁步骤见 [恢复说明](docs/RESTORE.md)。

## 启动

本工作区中双击 `启动工作台.cmd`，或运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-workbench.ps1
```

脚本使用映射的 `sources/deepseek-harness` 核心，将本地 `bkms-workbench` 安装到独立 Profile（邮件收发已内置，不再需要 dsh-email）。默认 HOME 为工作区 `runtime/dev/bkms-workbench/dsh-home`，端口 `9186`。不复制其他实例的模型密钥、邮箱账号或 Session。

首次进入 DSH 后，在设置中配置模型；在「工作台设置 → 信息源 → 邮箱」点「添加邮箱」，选服务商、填邮箱地址和授权码（邮箱设置中开启 IMAP/SMTP 后生成），可先「测试连接」再保存。然后打开侧栏的「任务工作台」：

1. 在「处理方案」新建方案，用一句话描述需求，点击「AI 生成」，核对后先「试运行」再保存；也可手动填写。
2. 开启后台处理。首次连接每个邮箱文件夹只建立收件基线，后续新邮件先经过 AI 分拣，再进入方案。
3. 「待我决策」三栏审核：左侧待办列表，中间 AI 产出（待核实事项在草稿正文中高亮），右侧原邮件、相关往来与记录。
4. 点击「预览并发送」（⌘/Ctrl + Enter），核对实际发件账号、To/Cc、正文、附件及收件人策略，再确认发送。

| 处理方案 | AI 分拣说明与开关；方案编辑为单页：一句话描述、适用范围（含语义条件和排除类别）、自主级别、处理要求、试运行 |

### AI 分拣

后台开启时，每封新邮件先读取正文并分类为请求、需回复、值得关注、通知、营销或其他，再在字面条件命中的方案中按「AI 匹配方案」的规则选择。通知和营销邮件默认不进入任何方案（方案可在「不处理这些类别」中调整），没有方案时在工作台内归档，不移动或修改邮箱中的原邮件。恢复某条归档后，该发件人的信息以后不再自动归档。未配置模型时用规则识别明显的通知与营销邮件，但不会替你选择需要 AI 确认的方案；可在设置中关闭分拣，恢复按字面条件匹配。

### AI 匹配方案

分类决定“要不要处理”，匹配决定“交给哪个方案”。每个方案有两种匹配方式：

- **AI 确认后处理**（默认，已有方案也按此处理）：字面条件只做初筛，AI 依据方案的「适用说明」、处理要求和学到的例子判断。把握高时直接处理，事项上显示匹配理由；把握一般或低时不处理，在“待我决策”里建议方案，由你点「按这个方案处理」或「不是这个」；没有可用的 AI（未配置模型或调用失败）时**不会凭字面条件猜测**，交给你选择。
- **字面命中就处理**：符合来源、文件夹和字面条件的信息都交给该方案，不需要 AI，适合“招聘简历”这类专用文件夹。

回信中引用的历史往来会被识别出来（QQ、Outlook、Gmail、网易、Foxmail、Apple Mail 及 `>` 引用等格式）：AI 以对方这次新写的内容来分类和处理，把历史往来当作上下文理解“这个价格”“上次的型号”等说法，不会把历史里已答复过的请求当成新请求；同一往来的上一封由某方案处理时，若仍是同一业务会优先沿用。原邮件的纯文本视图中，历史往来折叠显示。

你确认建议、手动选择方案，或在事项上点「不是这个方案」时，系统把这条信息的摘要记为该方案的正例或反例（每个方案保留最近 20 条，最近 8 条提供给 AI），在方案页可查看和删除。关闭 AI 分拣后，全部方案回到按字面条件匹配。

### 业务分类（投诉、查询、咨询…）

「处理方案 → 业务分类 → 新建分类方案」为一个邮箱文件夹定义业务分类，每封新邮件归入其中**一类**：

- **总说明**：分类之间怎么取舍，例如“同时有投诉和其他诉求时归投诉”。AI 优先按这段判断，没说到的按分类的先后顺序（越靠前越优先，可拖动或用箭头调整）。
- **每个分类**：名称、「属于本类」（定义和典型说法）、「不属于本类」（边界），以及动作：**只打标签**，或**移到文件夹**（不存在时自动创建，用这个邮箱的人都会看到变化）。最后固定有一个“其他”，AI 明确判断哪类都不是时归到这里。
- 归类在 AI 分拣的同一次调用里完成，不额外调用模型。**只有把握高时才直接归类**；拿不准的进入“待我决策 → 待分类”，按钮第一个是 AI 的首选，点一下就执行动作；可以勾选多封批量归类。在你选择之前，这封邮件不会自动交给处理方案。
- 打标签的邮件继续按处理方案处理（比如还能生成回复草稿）；移到文件夹的邮件移走后事项完成。
- 你的选择和更改都记为这个分类的例子（最近 6 条提供给 AI），在分类方案编辑页可查看和删除。
- 系统通知和营销邮件默认照常归档、不分类，可在分类方案里改为一起分类。业务分类需要开启 AI 分拣；同一个文件夹只能有一套启用的分类方案。
- 保存前先「试运行」：用最近 30 条，或「指定时间段」直接读邮箱（最多 30 封），显示各分类的数量和每封的判断，不建事项、不移动。
- “全部事项”可按业务分类筛选；每日简报和周报会统计各分类的数量。

**公共邮箱分给不同的人**：在公共邮箱收件箱上建分类方案，每个组一个分类、动作选「移到文件夹」（如 `客服/投诉`）；各组成员在自己的工作台里只读取本组文件夹。同一个公共邮箱的收件箱只能有一台工作台负责分类，否则同一封信会被处理两次。

以前建的“分派”处理方案仍然照常运行，新建方案不再提供这个选项。

### 我的资料与变量

「设置 → 我的资料」填写姓名、部门、角色、职务、电话、公司、签名和时区（不要填密码或密钥）。

- 处理要求里可以用变量引用这些资料和当前时间：`{{user.name}}` `{{user.department}}` `{{user.role}}` `{{user.title}}` `{{user.phone}}` `{{user.company}}` `{{user.signature}}` `{{today}}` `{{now}}` `{{weekday}}` `{{timezone}}` `{{mailbox}}`。在编辑框中输入 / 会列出变量，选一个即可插入，下方可预览“发给 AI 前的样子”；写错的变量名保存时会被拦下。没填的资料显示为“[未设置：…]”，AI 不会自己编。
- AI 处理和分拣时也会拿到“运行上下文”：现在的时间、时区、你是谁。它放在系统提示里，与邮件内容分开；角色和部门只影响措辞，不代表可以越权承诺。

### 从指定时间开始处理（补处理历史邮件）

「设置 → 高级与恢复 → 重建收件基线」可以选「从指定时间开始」：选邮箱、文件夹和开始时间后，先显示这段时间有多少封邮件（其中多少封已回复），确认后把这些邮件当作新邮件处理，用来快速验证方案。

- 一次最多 200 封，最早一年前；已在工作台里的邮件不会重复建事项。
- 已回复的邮件默认跳过，可勾选一起处理。
- 补处理的邮件**只生成草稿，不会自动发送**，即使方案开了自动发送。
- 如果这个文件夹的分类会移动邮件（或有以前建的分派方案），邮件会被真的移动，用这个邮箱的人都会看到。

只想看看方案准不准，先用方案页的「试运行 → 指定时间段」：直接读取邮箱中这段时间的邮件（最多 30 封，包括工作台开始处理之前的），只显示判断结果，不建事项、不移动、不发送。

### 自主级别

| 级别 | 行为 |
| --- | --- |
| 仅起草（默认） | 与原版一致：所有对外发送由你确认 |
| 低风险自动 | 模型判定为简单确认且通过下列检查的回复，在撤回窗口（默认 30 分钟）后自动发送 |
| 全自动 | 通过下列检查的回复在撤回窗口后自动发送，只建议用于完全信任的方案 |

自动发送前必须全部满足：没有待核实事项或阻塞，回复对象是单一邮箱，正文不含链接或其他邮箱地址，你从未撤回过发给该联系人的自动回复，长度在限制内；到点后仍通过邮件插件的发送预览与收件人策略，被禁止时转为人工审核。窗口内你修改、预览发送、忽略或重新处理该任务都会取消自动发送。已有方案默认仍为「仅起草」。

### 简报与报告

每日简报（默认 08:00）和周报草稿（默认周五 17:00）在后台开启时按时生成，也可手动生成；主题可设为每周随周报生成主题报告。有模型时由 AI 撰写，没有模型时用统计模板。输入只包含标题、摘要和状态，不包含完整邮件正文。报告只保存在工作台，不会自动发送。

### 信息源

已接入邮件和微信（只读）。微信通过内置的读取组件（移植自 wechatauto-replica，只需本机有 64 位 Python，无需另装）读取 Windows 微信 4.x 聊天记录，按联系人、群聊的白名单或黑名单处理，群聊默认只处理 @我 的消息；AI 写建议回复，由你复制到微信发送，工作台不发送微信消息。安装和隐私说明见 [docs/WECHAT.md](docs/WECHAT.md)。

飞书、企业微信和会议平台在界面中显示为「待接入」，需要实现 `src/sources.ts` 中的 `SourceAdapter` 后才能连接；工作台不会模拟未接入的来源。

原邮件可独立加载并下载附件；回复草稿可添加或移除附件。上传前需要先保存正文修改，上传后重新预览，避免发送旧版本内容。

关闭页面不影响后台；停止 DSH 服务会暂停处理，下次启动按游标补查。工作台加载期间自动抑制邮件插件的新邮件弹窗，卸载后恢复原通知偏好，不改写邮箱配置。

## 工作台设置

DSH 设置中的「工作台设置」集中管理显示与提醒、邮件检测及恢复；任务列表、AI 处理方案和草稿审核位于侧栏「任务工作台」。

- **显示工作台入口**：默认开启，可即时显示或隐藏侧栏入口。隐藏不暂停后台处理，设置入口始终保留。
- **新待办消息提醒**：默认关闭。开启后，在待审核、待补充、处理失败或发送待核实任务出现时显示简洁文字提醒；可点击查看待办或关闭，8 秒后自动收起。首次连接、重新开启和刷新页面只建立当前待办基线，不补弹历史任务；同一状态的草稿编辑和重复检测不会反复提醒。关闭后立即隐藏当前提醒。
- **邮件检查间隔**：30–3600 秒，默认沿用已有配置，仅在后台处理开启时生效。
- **邮件**：集中显示服务状态、最近检测时间；「高级与恢复」默认折叠，提供收件基线说明和重建入口。重建需选择邮箱及文件夹并明确确认，配置版本变化时需重新打开确认；不会补处理历史邮件。邮件设置每 10 秒刷新轻量状态，不加载任务正文或草稿。

偏好保存在当前实例的工作台数据中，与后台处理开关独立；隐藏入口或关闭提醒不会改动邮箱、处理方案、草稿和任务。工作台提醒只在 DSH 界面运行时显示，不申请系统通知权限；关闭页面后后台仍照常处理。

## 全局语言

工作台界面跟随 DSH 全局语言设置，支持中文与英文。侧栏和设置入口、任务状态、AI 处理方案、AI 创建、文件夹选择、运行记录及发送审核实时切换，日期也使用当前语言格式。切换不重建编辑器，未保存的描述、方案和草稿保持原样。

邮件主题、正文、用户方案名称、处理要求、附件名和邮箱自定义文件夹名属于业务内容，不会随界面切换自动翻译。新生成方案的名称与 AI 核对说明采用当前界面语言，处理要求和邮件语言遵循用户明确需求；原有方案不自动改写。已知系统提示在显示时翻译，第三方服务的未知原始错误和 SMTP 回执保留原文。

## 邮件写作与排版

新生成的回复默认使用简明主题、自然称呼、短段落、紧凑事项编号与适当结束语。规则的「处理要求」可自定义语言、语气及署名，例如“使用中文商务语气，署名为：张三 / 客户服务部”。未提供署名时不自动添加工作台品牌、姓名、联系方式或日期。

草稿以纯文本编辑和保存；「预览并发送」展示标准 HTML 邮件样式，实际发送同时携带 HTML 与纯文本版本。中文无衬线字体、14px 字号、1.65 倍行高和 12px 段间距，连续空白行仅在排版中收敛。工作台及邮件插件的草稿预览共用同一渲染器，正文中的 HTML 作为普通文字展示。

重新构建后完全退出 DSH 客户端（包括托盘）再打开。已保存的草稿可以直接使用新排版预览；新的写作规范在后续生成或重新生成时生效，历史内容与人工编辑不会自动改写。此前已发送邮件不会改变。

## 自定义实例

```powershell
powershell -File scripts/start-workbench.ps1 -DshHome D:/my-runtime/workbench -Profile my-workbench -Port 9187
powershell -File scripts/start-workbench.ps1 -Build -PrepareOnly
```

升级本地源码并构建后应重启 DSH 进程；依赖模块的热更新不等价于完整重启。

现有自定义 Profile 也可通过其对应 DSH 命令安装本地插件目录或 `pnpm run pack:plugin` 生成的 tgz，再重启。邮件收发已内置；之前装过 dsh-email 的 Profile 建议卸载它（工作台设置中会提示），邮箱账号需要在工作台里重新添加。不要把工作台直接装进其他用途的生产 HOME 做首次试验。

## 规则

方案列表仅展示方案名称、输出类型、邮箱与匹配条件等概要，不展开处理要求；点击「编辑方案」查看和修改完整内容。「全部任务」与「待我处理」均显示任务实际关联的处理方案名称（保留任务快照），未分配时显示「尚未匹配方案」。宽屏为独立列，窄屏显示在标题下方，长名称悬停可查看全文。

界面名称为「AI 处理方案」（英文 `AI workflows`），目前接入邮件；IM 等其他来源属于后续扩展。内部 `rules` 数据及已有配置保持兼容。新建默认选第一个已配置邮箱及其收件箱，优先级 100、全部条件满足、失败重试 1 次、生成处理摘要与回复草稿、保存后启用方案；全局后台开关单独控制。

邮箱文件夹从服务器读取为下拉选项，支持中文及层级路径，排除不可选容器；选择「全部邮箱」时只列共同路径。读取失败时保留当前选择并提供重试，不要求手工输入。默认收件箱使用邮箱配置中的 `inboxFolder`。

AI 使用 DSH 默认模型生成尚未保存的方案草稿，自动拆分名称、匹配条件、处理要求及必要的可用技能/查询工具。生成阶段不能读取邮件、执行业务或发送。界面展示实际匹配范围和待确认说明，再由用户保存；高级设置可调整筛选、优先级、重试与能力，也保留已有邮件的匹配测试。没有模型或生成失败时可手动填写。

「处理要求」右上角的 **AI 优化** 可将已有描述整理为简洁、清晰的步骤。保留原文供对照，点击「采用优化」才替换输入框，仍需「保存方案」；「保留原文」放弃建议。优化仅提交该输入框的文字给 DSH 默认模型，不读取邮箱，也不修改匹配范围、账号、工具及执行设置。界面切换英文不自动翻译业务要求。输入须为 5–16000 字；没有模型或请求失败时保留原文，可继续手动编辑。

更换客户端或重新安装本地插件后，需要从托盘完全退出客户端再启动。插件列表中的「已安装」只说明依赖存在；当前后台仍可能未加载刚加入的邮件服务。新客户端通常使用独立 HOME，旧实例的邮箱、处理方案及任务不会自动迁移；请先核对实例配置，再开启后台处理。

例如：“收到主题包含询价的邮件，整理客户需求并生成中文回复草稿，价格和交期缺少依据时列出待确认事项。”

目前筛选支持发件人包含、主题包含和有附件条件；正文语义、日期、金额或多个独立关键词等筛选不能直接表达。AI 会在待确认说明中提示受限要求，界面的匹配范围是执行依据，不把自然语言说明误当成额外筛选器。

- 多规则按优先级从高到低执行第一条匹配；同优先级按规则 ID 稳定排序。
- 发件人和主题使用不区分大小写的包含匹配，可配置全部条件或任一条件成立。空条件匹配该范围的全部新邮件。
- 规则保存为任务的版本快照；修改或删除规则不影响已排队任务。
- 「测试匹配」仅测试条件，不调用模型。未匹配邮件在「全部任务」中可手动选规则处理。
- 所选技能仅加载其处理说明，不自动扩大工具权限。附件分析需要选择已安装的可信读取工具，例如 `read_document`，文本附件可使用 `str_replace_editor` 的 `view`。
- 默认不开放后台写入和发送。工具目录按已知危险名称过滤；第三方工具没有统一只读声明，仍须确认所选工具实现可信。
- 自动重试最多 3 次；单次 DSH 准备任务最长 5 分钟，串行执行以限制成本和并发冲突。

## 审核与恢复

「AI 处理方案」采用紧凑列表，显示名称、输出类型、适用邮箱与筛选条件，右侧可启停或编辑；完整要求在编辑页面中查看。邮件检查间隔统一在 DSH「设置 → 工作台设置 → 邮件」配置，对全部方案生效。

方案新建/编辑与邮件任务审核均在工作台内部完整页面中进行，左上角使用「箭头 + 当前内容标题」作为返回入口，点击箭头或标题返回原列表并保留搜索、筛选及滚动位置；悬停提示具体返回位置。方案页采用「方案内容」「适用范围与选项」两个全宽页签，分别编辑处理要求和配置邮箱、筛选条件与能力，AI 核对说明折叠查看。切换页签保留未保存内容，顶部统一保存整个方案并留在当前页；有无效字段时自动切换到对应页签并定位。邮件页宽屏并排查看原邮件与处理结果，窄屏切换内容，底部固定保存与发送操作。长处理要求和草稿正文随内容增高；未保存的方案、草稿或补充信息在返回时提示确认。最终发送预览、忽略任务及重建基线仍使用确认弹窗。

分析报告与回复草稿按方案的输出类型分别处理。报告不要求回复正文或署名；不影响核心分析的资料缺口单列为「待人工核实」，任务正常完成。只有无法继续核心处理时才进入「待补充」；附件读取或解析受阻时单独提示检查读取工具与附件格式，不把缺少依据当作不符合要求。

补充资料会累计保留，合计最多 16000 字。已有任务继续保留原方案快照；修改处理要求或新增 `read_document` 等能力后，可在任务详情选择「按最新方案重新处理」，确认后使用当前配置，并一并提交输入框中的补充资料。旧结果保留在处理记录，原草稿保留，不自动发送。「按原方案重试」和直接提交补充信息仍使用原快照。

方案保存的成功、失败及字段校验反馈固定在标题下方，不随内容滚动消失；保存期间防止重复提交。保存已成功但列表刷新失败时会明确提示，并保留新方案 ID，避免再次保存重复创建。

草稿由内置邮件模块保存，工作台任务关联其 ID。人工修改有版本检查；重新生成保留原草稿并创建新的草稿，避免覆盖人工内容。草稿最多 500 份、总存储最多 16 MiB，附件上限 20 MiB。

只有明确确认当前预览才发送。收件人禁止规则、账号变化、草稿变化和预览过期会阻止发送。SMTP 接受表示获得提交回执，不保证对方最终投递成功。结果不明不会自动重发，需先核对邮箱。

「发送待核实」任务提供「确认未发送，恢复草稿」和「确认已发送，标记完成」，再次勾选核对结果才生效。前者保留草稿并返回待审核，修复连接后需要重新预览、手动发送；后者记录人工核对，不生成 SMTP 回执。两种操作均不发送邮件，原错误保留在核对/任务记录。能明确判断为连接建立前失败的发送直接返回待审核；提交阶段不明确的超时仍需核实，不自动解锁或重发。

UIDVALIDITY 变化会停止相应文件夹的增量处理。在「设置 → 工作台设置 → 邮件 → 高级与恢复」的「重建收件基线」确认后恢复；重建时现有邮件不会补处理。

任务存储在 `$DSH_HOME/data/bkms-workbench/workbench-v1.json`，附件位于该目录 `tasks/<任务ID>/`，邮箱账号和草稿在该目录 `mail/`（`accounts.json` 含授权码，权限 0600）。整个目录一起备份。每个 HOME 只允许一个后台 worker；数据写入使用文件锁和原子替换。损坏文件保留并报错，不自动覆盖。

原附件的下载副本暂不自动清理，重复下载会增加本地磁盘占用。任务数据达到 5000 项或 64 MiB 时停止追加并报错，需要先备份归档。

## 当前边界

原邮件阅读区采用独立浅色信头，显示主题、发件人、收件人、抄送、时间及可用的邮件大小；旧任务没有完整收件人时显示收件账号，不推测地址。附件位于正文上方，显示文件图标、类型、文件名及大小，沿用原下载入口。邮件模块按 MIME 分段额外读取 HTML（上限 256 KiB，不为显示下载附件），工作台提供「原始排版 / 纯文本」切换；旧任务点击「重新读取原邮件」获取新显示资料。HTML 仅用于阅读，模型继续使用原纯文本。

HTML 通过惰性模板解析，重建允许的展示元素和内联样式，再放入禁止脚本及同源权限的 sandbox iframe；CSP 阻止远程图片、样式、表单与其他资源，原邮件链接不带导航能力。不加载外部图片或样式，不能保证与完整邮件客户端逐像素一致；无法获取 HTML 或超限时回退纯文本，并压缩连续空行。

当前以每封邮件建立任务；同一业务的多封补充邮件自动归并、多人分派、业务系统写入、可视化流程画布尚未实现。报告输出为任务内文本摘要；外部文件生成不是本版默认后台能力。没有配置账号及模型前，工作台仅提供配置和查看入口。
